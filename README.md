# دفتر الشراكة — نظام داخلي للأرباح والسحوبات

هذا المشروع نسخة مستقلة جاهزة للتشغيل لنظام داخلي بين عزام ووسيم. لا يمثل بنكًا أو محفظة مالية حقيقية.

## المكونات
- Node.js + Express
- SQLite + better-sqlite3
- JWT في HttpOnly cookie للمصادقة
- واجهة عربية RTL متجاوبة بدون إطار Frontend ثقيل
- Ledger تراكمي مستقل لكل شريك
- إعدادات نسب الشراكة والاحتفاظ والتوزيع وحدود السحب
- تقارير أسبوعية وشهرية وفترة مخصصة
- Audit Log
- Migration versioning
- اختبارات للحسابات الأساسية

## المتطلبات
Node.js 22+ لأن المشروع يستخدم واجهة SQLite المدمجة `node:sqlite`.

## التشغيل
```bash
npm run migrate
npm run seed
npm start
```
ثم افتح `http://localhost:3000`.

## قاعدة الحساب
`صافي الربح = الدخل - المصروفات التشغيلية`

السحوبات الشخصية لا تدخل في المصروفات التشغيلية. بعد حساب صافي الربح:

`المحتفظ به = صافي الربح × نسبة الاحتفاظ`

`المخصص للتوزيع = صافي الربح × نسبة التوزيع`

ثم:

`حصة الشريك = المخصص للتوزيع × نسبة الشريك`

ويضاف الناتج إلى Ledger الشريك. السحب الشخصي يطرح من Ledger ذلك الشريك فقط.

## الحفاظ على التاريخ
التعديلات على العمليات لا تحذف السجل الأصلي مباشرة؛ الحذف المنطقي عبر `deleted_at` مع Audit Log. ويتم إعادة بناء قيود تخصيص الأرباح تلقائيًا بعد تغيير أو إلغاء دخل/مصروف أو تغيير إعدادات، مع ربط الفترات التاريخية بإعدادات كانت سارية في نهاية الفترة.

## Migration
ملف `db/migrations/001_initial.sql` هو Migration آمنة أولية. تشغيل `npm run migrate` قابل للتكرار ولن يعيد تطبيق Migration مطبقة سابقًا.

## ملاحظات دمج مع نظام قائم
بما أن المصدر الأصلي للموقع غير متاح هنا، هذه النسخة لا تدّعي الحفاظ على كود أو جداول غير مرئية. عند توفير المشروع الأصلي يمكن نقل نموذج Ledger والحسابات والواجهات إليه عبر Migration إضافية مع mapping للبيانات القديمة.
